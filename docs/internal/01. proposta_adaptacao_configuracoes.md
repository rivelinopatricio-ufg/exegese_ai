## 2. Class JavaDoc & Author Tag
Every Java class, interface, enum, and record MUST include a class-level JavaDoc block containing the `@author Rivelino Patrício` tag.

Example:
```java
/**
 * Description of the class purpose and responsibilities.
 *
 * @author Rivelino Patrício
 */
```

## 3. Language Standards
- **Source Code Comments**: All code comments, JavaDoc descriptions, `@param` / `@return` tags, inline explanations, and implementation notes within source code (Java, JavaScript, CSS, etc.) MUST be written in **English**.
- **Instruction & Documentation Files**: All project-level instructions, rules, markdown guides, and architectural documentation (such as `GEMINI.md`, `AGENTS.md`, and files under `.agents/`) MUST be written in **English**.
- **Commit Messages**: All suggested or drafted git commit messages MUST ALWAYS be in **English**, MUST strictly follow the **Conventional Commits** standard, and MUST be **concise**.

## 4. File Encoding & Artifact Standards
- **UTF-8 Mandatory**: All source code, artifacts, configuration files, scripts, properties files, and markdown documentation MUST be encoded in **UTF-8** (without BOM).
- **Special Characters & Accents**: Always preserve proper encoding for internationalization (i18n), special characters, and diacritics.
- **PowerShell / Windows Commands**: When piping or writing file outputs using PowerShell or terminal commands, always enforce UTF-8 (e.g. use `-Encoding utf8` or ensure standard UTF-8 stream output) to avoid Windows-1252 / ANSI fallback.

## 5. RAG Architectural Standards & Strict Factual Grounding
- **Zero Hallucination Policy**: All generation generated by RAG pipelines must be 100% grounded on indexed chunks. If no relevant chunks are found, return clear abstention.
- **Multi-Collection Isolation**: Vector and hybrid queries MUST always filter by `collection_id` (e.g. `exegese_vector_store.collection_id = :targetCollection`).
- **Canonical Citation**: Every generated answer must provide canonical citations (document name, section/question number, page number) formatted for presentation in UI modals/popovers.
- **Idempotent Ingestion**: Chunks must be hashed (`chunk_hash` SHA-256) to ensure idempotent re-indexing without vector duplication.

## 6. Dependency Injection Standards (Constructor Injection Mandatory)
- **Constructor Injection Mandatory**: In all Spring components, controllers, services, repositories, and configuration classes, dependency injection MUST be performed via **constructor parameter injection** (`JAVA_CONSTRUCTOR_PARAMETER_INJECTION`).
- **No Field Injection**: Never use `@Autowired` on private/protected fields.
- **Immutability (`final`)**: Injected dependency fields MUST be declared as `private final`.
- **Optional Dependencies**: When a bean dependency is optional (e.g., conditionally loaded services), inject it as `Optional<T>` in the constructor parameters (e.g., `Optional<MyService> myService`) and unwrap it in the constructor (`this.myService = myService.orElse(null);`).
- **Spring 4.3+ Clean Syntax**: When a class has a single constructor, omit the `@Autowired` annotation on the constructor itself, as Spring injects single-constructor parameters implicitly.

## 7. Git Commit Policy (No Autonomous Commits)
- **Never Autonomous Commits**: The AI assistant MUST NEVER autonomously execute `git commit`, `git push`, or create Git commits under any circumstances unless the user explicitly and directly requests a commit in that specific prompt.
- **Working Tree Preservation**: All code, configuration, and file modifications MUST remain in the working tree (uncommitted) so that the user has complete control over reviewing diffs, running tests, and managing the repository history.
- **Suggestions Only**: The assistant may provide concise change summaries or suggest commit messages when relevant, but must leave the execution of `git commit` and `git push` entirely to the user.
- **Conventional Commits Mandatory**: All suggested or drafted commit messages MUST strictly adhere to the **Conventional Commits** specification (`<type>(<scope>): <subject>` or `<type>: <subject>`), utilizing standard types (`feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`).
- **English & Conciseness Mandatory**: All suggested or drafted commit messages MUST ALWAYS be in **English** and MUST be strictly **concise**.

## 8. Implementation Plans & IDE Artifact Presentation
- **Mandatory Markdown Plan File**: Whenever designing, specifying, or executing an architectural or implementation plan, the assistant MUST create or update the plan as a dedicated Markdown document stored under `docs/` and as a user-facing Artifact in the IDE.
- **IDE Display Only (Never dump full plan in Chat)**: The assistant must display/render the full plan in the IDE interface (via Artifact with `UserFacing: true` or file viewer) and MUST NOT output the full plan markdown content into the chat conversation. The chat response must contain only a concise executive summary, status of execution, and direct file links to the plan document in the IDE.
```

```yaml
version: "3.8"
services:
  postgres:
    image: pgvector/pgvector:pg17
    container_name: exegese_postgres
    environment:
      POSTGRES_DB: exegese_db
      POSTGRES_USER: exegese_user
      POSTGRES_PASSWORD: exegese_password
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped

  app:
    image: exegese_ai:latest
    container_name: exegese_app
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8080:8080"

      SPRING_PROFILES_ACTIVE: local

      SPRING_DATASOURCE_USERNAME: exegese_user
      SPRING_DATASOURCE_PASSWORD: exegese_password
    depends_on:
      - postgres
    restart: unless-stopped

volumes:
  pgdata:
    driver: local
